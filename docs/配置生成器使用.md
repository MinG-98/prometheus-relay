# Prometheus Relay 配置说明

VPS 部署请直接使用网页控制台。仓库中的 `docs/index.html` 仅为源码模式兼容保留，用于生成旧式环境变量配置；项目不再通过 GitHub Actions 执行真实账号任务。

## 常用参数

| 名称 | 说明 | 建议 |
| --- | --- | --- |
| 消息模板 | 实际发送的文本；`[API]` 会替换为一条“一言” | 先使用固定短文本测试 |
| 好友匹配方式 | 按抖音号或原始昵称查找好友 | 优先使用抖音号 |
| 浏览器超时 | 单次浏览器操作最大等待时间 | 网络较慢时适当增加 |
| 好友加载等待 | 打开好友列表后的额外等待时间 | 默认即可 |
| 失败重试次数 | 单个任务失败后的重试上限 | 建议 1–3 次 |
| 日志级别 | Error、Warning、Info 或 Debug | 日常使用 Info，排错时 Debug |

## 扫码添加账号（推荐）

1. 在网页控制台点击“扫码添加”。
2. 等待 VPS 中的无头浏览器生成抖音登录二维码。
3. 使用抖音 App 的“扫一扫”扫码，并在手机上确认登录。
4. 如果抖音要求完成安全验证，VPS 会在官方验证页面中选择短信验证方式，并等待输入框就绪。
5. 验证码发送到绑定手机后，将验证码填入网页中出现的输入框，点击“提交验证码”。验证码只接受 4–8 位数字。
6. 验证通过后，控制台会自动抓取这次浏览器会话的 Cookie，并识别昵称和抖音号。
7. 确认显示的账号身份正确，打开新增账号，填写目标好友后保存配置。

二维码、浏览器会话和短信验证码只保存在 Web 进程内存中。登录完成后，Cookie 会写入 VPS 私有数据卷；网页接口不会返回 Cookie 内容。重复扫描同一账号会更新 Cookie，并保留已有目标好友。

### 短信验证排查

- “正在准备短信验证”表示 VPS 仍在识别抖音官方验证页面，请保持扫码窗口打开，不要立即重复扫码。
- 输入框出现后再提交验证码；提交后页面可能需要一些时间完成官方验证。
- 如果提交后重新显示输入框，说明本次验证码没有通过。确认使用最新验证码后再提交，不要连续高频重复提交。
- 如果会话过期或二维码失效，重新开始扫码登录。重新扫码前不要关闭正在进行的验证窗口。
- 登录成功后，先核对网页显示的抖音号和昵称，避免把错误账号保存到 VPS。

验证码提交后会从服务器内存中清除，不会写入配置文件、Cookie 或日志。

## 手动配置 Cookie（备用）

1. 在自己的浏览器中登录[抖音创作者中心](https://creator.douyin.com/)。
2. 在账号页面记录显示名称与抖音号。
3. 保持该页面登录，使用 Cookie-Editor 等扩展导出 JSON。
4. 回到 Prometheus Relay 网页控制台，点击“手动添加”并上传刚导出的 JSON 文件。

Cookie 等同于登录凭证。控制台保存后只显示 Cookie 数量，不会回显内容。不要将 Cookie 上传到 GitHub、Issue 或任何公共服务。

## 获取目标好友

推荐填写好友抖音号。可以在抖音 App 的好友主页查看，也可在创作者中心的私信页面打开好友资料后查看。每行填写一个目标；重复项会自动去除。

昵称模式只应作为无法取得抖音号时的备选，因为昵称可能变化或重名。

## 首次验证

保存后先点击“立即运行”，确认执行记录成功且目标好友收到消息，再开启每日自动运行。不要通过高频重试来测试，以免触发平台风控。
